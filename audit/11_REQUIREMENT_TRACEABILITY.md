# 11 — Canonical Requirement Traceability Matrix

This matrix maps every canonical product requirement (§2–§3) to its actual implementation location in `Sources/MacPulseNative/`, its true test coverage (distinguishing real binary/Objective-C tests from fake inline Python mocks), its verification classification (§1.4), and remaining gaps.

## Verification Classification Legend (§1.4)
- **STATIC:** Verified by source code, configuration, or binary header inspection.
- **AUTO-LOCAL:** Verified by automated local build, self-test, or E2E/stress binary execution against real Objective-C production code.
- **RUNTIME:** Verified on the live running macOS 26.2 (`arm64`) host (`PID 16618`, `pmset -g assertions`, `ps`/`top`).
- **HARDWARE:** Requires physical hardware transition (charger plug/unplug, battery drain, lid close, Intel Mac, desktop Mac).
- **NOT VERIFIED:** Evidence unavailable or physical hardware test not executed.
